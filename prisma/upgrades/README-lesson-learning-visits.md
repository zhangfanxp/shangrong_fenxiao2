# 课时学习记录：逐次进入记录

## 统计口径

- 本次上线后，一次成功进入课时页面生成一条独立记录。返回后再进入、刷新页面、在另一标签页进入都会生成新记录；网络重试和 React 开发模式探测不会重复生成。
- 记录课程、章节、学习人快照，开始/结束时间由服务端确认并统一按上海时区展示。完成课时不等于退出页面，不提前填写结束时间。
- “学习记录”按当前批次课程及接收人筛选其共享学习历史，不限定产生记录的分配批次，也不因重复分配重置进度。总条数是记录数，不是去重人数；旧数据明确作为历史汇总展示，不能当成真实进入次数。
- “未学习人员”继续以有效课时进度/完成为依据。只进入未学习的用户可以同时出现在两个 Tab 中，不视为矛盾。
- 正常返回、站内离开、浏览器 `pagehide` 上报结束；正在学习显示“学习中”。页面隐藏只上报活跃，不当作确认退出，避免把切换应用、打开 PDF 新窗口误记为正常结束。
- 可见页面每 30 秒上报活跃，进度保存也更新活跃时间。超过 120 秒没有活跃信号时显示“异常结束”及最后活跃时间，不伪造退出时刻。手机强关、断网等无法可靠收到退出事件；恢复时需点击重试建立新记录。超时状态在读取时即时判断，不依赖定时任务；后续写请求会固化中断状态。
- 已结束/中断记录不可重新打开；重复关闭不覆盖原结束时间。接口绑定当前登录用户、移动端、课程和课时，进度写入必须关联有效记录，并重新检查学习资格。
- 章节/学习人保留进入时快照；列表课程名称继续使用分配批次快照。课时删除/改名不影响已保存的访问明细。

## 现有数据库升级

1. 备份目标数据库，暂停移动端学习写入；核对已执行 `20260831_course_assignment_batches.sql`。若原批次功能尚未部署，请先按同目录批次升级说明处理。
2. 核对 `DATABASE_URL` 后执行一次：

   ```sh
   npx prisma db execute --file prisma/upgrades/20260831_lesson_learning_visits.sql --schema prisma/schema.prisma
   npx prisma generate
   ```

   SQL 新增 `CourseLessonVisit`，不会修改原课程/课时学习进度。有有效旧课时进度的记录按“用户 + 课时”导入一条 `LEGACY` 汇总；仅有课程进度时保留课程汇总并标记章节未知。旧开始/结束时间均为空，界面显示“历史数据未采集”，不把累计进度创建时间冒充某次进入时间。历史章节名称取升级时能获取的资料，不声称还原旧名称。

   MySQL DDL 不能整段事务回滚。脚本只执行一次；若中途失败，先核对已建表与已导入数据再处理，不能直接重跑、清表或重置数据库。已有库不要使用 `db push` 代替该升级，否则历史汇总不会导入。
3. 构建并重启服务，使新版 Prisma Client 和两套移动端代码同时生效；恢复访问。旧版已打开页面需刷新，因为进度接口新增必填 `visitId`。

全新空库可以直接应用完整 schema，无需再执行这两个增量建表脚本。

## 验证

```sh
npx tsx scripts/verify-lesson-visit-tracker.ts
# 下列集成测试仅允许本机 canyin_assignment_test_* 空库，先应用完整 schema。
npx tsx scripts/verify-course-assignments.ts
npx tsc --noEmit
npm run build
```

集成脚本会调用 `verify-lesson-visits.ts`，覆盖并发幂等、反复进入、正常退出、超时、资格撤销、快照、分页、双移动端请求校验及原学习进度不变。升级验证使用另一个隔离空库：先应用没有 `CourseLessonVisit` 的上一版 schema，运行 `verify-lesson-visit-upgrade.ts --seed`，执行增量 SQL，再运行 `--verify`，最后做 Prisma schema diff。

界面验收：分别从运营移动端和门店员工移动端进入同一课时两次并返回；后台查看对应分配的学习记录，应该有两条开始/结束明细。保留一条不退出时显示“学习中”；模拟网络中断超过两分钟，刷新后台后应显示“异常结束”，不出现虚构结束时间。
